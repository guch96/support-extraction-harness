# 客户对话提取 Harness：设计规格

日期：2026-10-18。状态：单提取 Agent 设计已于 2026-10-19 实施；验证见[README](../../README.md)与[真实模型评测报告](../EVALUATION.md)。当前拓扑由 ADR-0008 替代原双角色方案。

本文按 `grilling` 的逐轮决策和 `domain-modeling` 的领域建模方式整理，是当前需求与验收的主入口。[PRD](../PRD_DESIGN_DRAFT.md)保存原题与最新决策摘要；[设计评审稿](../DESIGN_REVIEW.md)提供架构图与控制流；[上下文契约](../PROMPT_CONTEXT.md)定义模型输入、首次提取、修复、页面和交接话术；[术语表](../../GLOSSARY.md)定义领域语言，[ADR](../adr/)记录架构取舍。实现参数由后续实施计划落实，不能覆盖本文已确认的行为边界。

## 1. 目的与范围

本项目用于 AI 后端工程师招聘评估，重点展示围绕非确定性模型建立可预测、可测试、可观测控制流程的能力。成功交付必须能演示正常提取、输出修复、修复耗尽后的人工接管，以及输入和工具内容的注入缓解。

| 来源 | 本次交付 |
|---|---|
| 原题硬性要求 | 六字段强类型提取；JSON/schema 校验；原始失败输出和错误签名；有限修复；人工审核兜底；提示词注入缓解；结构化日志；自动化测试；架构、取舍与生产扩展说明 |
| 已确认扩展 | LangChain 原生 middleware；独立 Harness；一个无业务工具的提取 Agent；代码授权并读取只读 fixture；SQLite 会话记忆；FastAPI + Gradio；聊天式演示（替换原表单页）；敏感原文与脱敏来源的不同生命周期 |
| 范围之外 | CLI、真实业务修改、操作预览、模型可调用业务工具或工具审批、SSE/WebSocket 传输、静态回放、追问解释、人工编辑或关闭审核、自动重放中断请求、长期记忆、通用 LLM 裁判、公网多用户账户系统、分布式生产部署；双角色仅作为未来独立演示的可选方向，不进入本次必需交付 |

用户已取消开发时间限制，仍按招聘评估目的控制功能范围。私有 GitHub/GitLab 仓库的创建与提交由后续任务决定。

## 2. 模块边界与数据流

依赖方向为 FastAPI / Gradio → 应用组装 → 独立 Harness。Harness 接受领域输入、可信运行上下文和注入能力，返回领域结果或领域错误；核心不依赖 Web 框架、HTTP 对象或 Gradio State。

| 模块 | 责任 |
|---|---|
| Harness | 可信来源请求的执行控制、输入安全与上下文构造、模型调用、严格校验、唯一修复循环、预算和终止状态 |
| 本题应用 | 六字段 schema、分类与紧急程度规则、PII 检测规则、基准及攻击 fixture |
| 基础设施 | 模型供应商、受控来源读取适配器、SQLite 会话映射与提取 checkpoint、原文审计和人工审核存储 |
| 入口 | FastAPI 请求与 HTTP 映射；Gradio 交互、会话恢复、结果和审核展示 |

模型、持久化、审计与审核能力通过接口注入。调用方无需启动 Web 服务即可使用 Harness；外层入口不得绕过它直接调用模型。

直接文本和记录读取模式共用同一个提取 Agent，首次提取与修复使用同一模型配置。记录读取由代码依据可信请求执行：检查允许的读取适配器、严格参数、请求绑定的资源范围和次数，再读取固定记录；实际返回内容仍是不可信来源。提取 Agent 不选择记录、不注册业务工具，读取结果在安全处理与持久化后进入同一提取流程。

记录读取模式用于取得新任务的原始对话；同任务后续补充基于已保存来源，不再次加载原记录。切换到另一份记录建立新任务，避免混入另一客户事实。资源允许范围由应用配置或可信调用方绑定，不能由请求正文自行声明。

固定记录读取没有需要模型自主规划的步骤，因此主链采用单 Agent；授权、状态转换和失败接管均由程序决定。当前取舍见 [ADR-0008](../adr/0008-use-one-tool-free-extraction-agent.md)，替代旧 ADR-0001；模块独立性仍按 [ADR-0003](../adr/0003-keep-harness-independent-of-entrypoints.md)。

每次模型请求重新构造：固定 system + 当前任务完整的安全来源包；修复时仅增加当前运行上一次失败的安全反馈包。system 不含来源原文，来源与失败正文不成为可信指令。来源版本和 PII 标记由宿主生成；历史模型答案、旧修复对话和其他任务材料不自动回放。具体结构与话术以[上下文契约](../PROMPT_CONTEXT.md)为准。

## 3. 提取与执行契约

模型返回纯 JSON 对象，六个字段均必须出现；采用严格类型并拒绝额外字段。

| 字段 | 类型与约束 |
|---|---|
| `customer_id` | string 或 null；无明确标识时为 null，字段不能省略 |
| `issue_category` | BILLING / TECHNICAL / ACCOUNT / OTHER |
| `urgency` | LOW / MEDIUM / HIGH / CRITICAL |
| `summary` | string，最多 200 个 Unicode 码点 |
| `actionable_steps` | list[string]，原文明确的后续步骤或解决事项；无明确事项时可为空 |
| `detected_pii` | boolean，表示本任务来源材料中是否曾出现敏感数据 |

禁止通过剥离 Markdown、补缺失字段、隐式类型转换、截断摘要或替换非法枚举来掩盖模型输出错误。JSON/schema 错误必须进入同一修复循环。

运行时检查包括原始响应的 JSON/schema 校验，以及显式的 PII 合并和安全脱敏处理；交付数据仍须通过同一 schema。后处理造成字段约束失败时进入既有修复出口，共用预算。分类、紧急程度和事实真实性按业务样例单独评测，不以关键词规则或另一模型裁判冒充事实证明。

六字段外另有执行结果：关联 session/task/request 标识、执行状态、有效数据或审核引用、调用及修复计数和稳定失败原因。具体字段命名在接口设计中落实，必须满足以下语义：

| 执行状态 | 含义 |
|---|---|
| SUCCESS | 首次提取通过已声明检查 |
| REPAIRED | 至少发起一次输出修复，随后通过相同检查 |
| FALLBACK | 未取得可接受结果，且人工审核记录已可靠保存 |

FALLBACK 的本次有效数据为空，不能使用历史有效结果冒充成功。审核保存失败为服务错误，不能返回虚假的审核 ID。成功仅代表通过检查，不代表所有业务事实已证实，也不构成操作授权。

## 4. 唯一修复循环与失败出口

提取 Agent 不注册业务工具，返回 JSON 文本；LangChain 原生 middleware 校验真实响应并唯一控制修复。每次失败保存原始响应、错误签名和具体约束，随后通过图跳转再次生成。错误签名由安全字段路径和错误类型组成，不含敏感原值；未知字段名不能直接成为可信错误文本。

空响应、非预期非文本响应或任何模型工具调用均为输出协议错误，不执行工具，进入同一有限修复预算；即使同时带有合法 JSON 也不能当作合格响应。调用本身抛出的网络或鉴权异常仍走调用失败出口，不与这些输出错误混淆。

修复输入携带对应失败输出的安全处理副本、错误签名和具体约束，并保持失败文本的不可信身份。原始证据与修复副本通过 request/attempt 关联；校验依据本次原始响应，不重新解析脱敏副本来替换原始错误结论。每次修复重新经过输入安全、计时与预算控制。

| 单次运行预算 | 上限 |
|---|---:|
| 额外输出修复 | 2 |
| 提取模型调用，两种输入模式统一 | 3 |
| 指定记录实际读取 | 1；直接文本和已接收来源的补充为 0 |

JSON 与 schema 错误共享修复预算。关闭 SDK 自动网络重试，不叠加 ToolStrategy 自动纠错、wrapper 内重试或外层整次重跑。模型超时、鉴权及来源读取异常不触发格式修复；失败模型调用仍计入实际调用次数并记录耗时。来源在同一次运行中固定，修复不重新读取记录。模型调用与整体运行均设置有限超时，具体数值由实施计划配置。

预算耗尽、预期模型或来源读取失败通过统一失败出口保存 PENDING 审核项；读取失败时记录请求与原因，不能伪造未取得的对话原文。读取授权拒绝形成 AccessDenied，实际读取与模型均不执行；策略自身异常停止读取并返回服务错误。不可预期内部故障和审计/审核持久化故障形成明确服务错误。必要审计覆盖调用异常、图跳转和终止路径，不能仅依赖可能被跳过的 after hook。恢复所有权见 [ADR-0002](../adr/0002-own-repair-loop-in-native-middleware.md)。

## 5. 注入缓解与信息保护

支持对话、补充、读取记录、失败输出及历史材料均是不可信数据。模型可见内容先检测 PII、脱敏并中和伪造角色/边界标记，再进行安全序列化和边界包装；可信系统指令声明这些内容只能用于提取。随机边界属于提示层缓解，不能证明模型必然忽略攻击。安全处理异常时停止模型外发，进入明确服务错误出口；不能以原文代替脱敏失败的材料继续调用。

提取 Agent 没有可调用的业务工具。来源读取的白名单、严格参数、资源范围和次数由代码在执行前检查；资源授权来自可信运行上下文，不能来自客户文字、模型生成参数或记忆。只有代码选定的来源读取路径能执行，不处理模型发出的工具调用、多工具批次或扩权请求。

来源适配器只向安全处理流程交付预期文本，不把错误原文、任意元数据或外部指令投影进模型上下文。主链不创建模型工具调用/ToolMessage 配对，也不依赖 return_direct 终止。最终行动项和摘要仅用于展示，不能作为命令或自动执行的依据；默认不流式展示未经校验的模型文本。测试检查实际模型输入、工具配置、读取次数与存储，验证这些边界。

PII 至少覆盖完整信用卡号、身份证/NRIC 与显式密码语境；卡号尾号不单独触发。宿主原文检测、通过校验的模型判断与本任务历史标记取 OR。撤回、业务修正或脱敏不清除曾出现标记，新任务重新判断；失败模型输出不构成来源 PII 证据。文档需说明检测误报、漏报限制。

普通日志、错误响应和默认页面只含脱敏内容或原文引用。原文存储 Git 排除，SQLite 文件限制为服务用户访问，部署限定本地回环；原文仅通过本地受控审核入口显式查看。默认关闭原文外部 tracing，不宣称 SQLite 已加密或本地方案提供公网多租户访问控制。聊天页只展示已校验字段；未校验的模型原始响应仅在审核入口显式查看，页面默认不展示也不流式输出。

## 6. 来源材料与会话生命周期

session 标识连续交互，task 标识一份对话及其补充，request 标识一次提交触发的运行。提取 thread 稳定关联 session + task + 固定 extractor 命名空间；SQLite 保存当前任务映射、来源版本和提取上下文，重启后原 sessionId 能恢复。固定命名空间不意味着存在多个角色。见 [ADR-0004](../adr/0004-persist-session-context-in-sqlite.md)。

### 6.1 接收补充与模型成功分开

直接提交的对话、代码读取的记录与同任务补充通过接收检查和安全处理后，先可靠保存来源、对应脱敏材料及必要关联，再调用模型。保存失败时不调用模型；超限或并发拒绝的提交不进入来源历史。记录读取模式在保存前完成代码授权和取数，来源版本与运行关联必须可查，不能把读取成功等同于来源已可靠保存。

已保存的补充不因后续 FALLBACK、中断或内部处理失败而撤销。下一次提交依据这些材料继续提取，最新明确修正优先；旧有效结果仅用于标明所属运行的历史展示。保存补充与提取成功是两个事实，模型失败不代表补充未接收。

例如原客户 ID 为 CUST-123，后续修正为 CUST-456 的运行进入 FALLBACK；再次仅补充“仍未解决”时，来源中的客户 ID 仍为 CUST-456。取舍见 [ADR-0007](../adr/0007-persist-source-before-extraction.md)。

### 6.2 原文与脱敏来源分别保留

首次接收时分别保存受控原文与脱敏来源材料。脱敏来源按原顺序保留补充和明确修正，是后续模型输入的依据；它不是模型生成摘要。历史答案和修复对话用于展示或审计，不自动成为新事实或下一次运行的输入。

| 内容 | 生命周期 |
|---|---|
| 会话及脱敏来源、提取上下文 | 默认连续七天未使用后过期，可配置；显式清空立即使旧 sessionId 无法恢复 |
| 原始来源、每次模型原始输出 | 各自按保存时间默认保留七天；活跃会话不延长原文保留 |
| 本次运行计数、失败和输出 | 每次新提交初始化，累计展示统计不作为预算 |

原文到期后继续使用保留的脱敏来源；审核入口明确显示“原文已过期”，不能宣称完整原文仍可取回。追加材料、恢复会话或生成新审核项均不能复制旧原文来延长其保留期。脱敏损失的信息不得通过旧模型答案或猜测补齐。取舍见 [ADR-0006](../adr/0006-separate-source-and-raw-retention.md)。

新任务、新会话不继承其他客户事实。历史模型输入同样经过安全处理，checkpoint 只保存安全内容及必要引用。来源材料超过配置上限时明确拒绝追加，不静默截断或自动摘要；同任务并发提交拒绝重入。

### 6.3 中断与重启

重启不刷新会话最后使用时间，也不自动续跑中断模型调用。中断运行保留 requestId、已发生的尝试与计数，记录中断原因并可靠转人工；保存失败为服务错误。已接收来源继续保留，用户再次提交创建新 requestId 和新运行预算。SQLite 不保证供应商调用 exactly-once，未知调用结果不能视为可安全重试。见 [ADR-0005](../adr/0005-do-not-replay-interrupted-model-calls.md)。

## 7. 可观测性、入口与人工接管

结构化事件关联 session/task/request、source_revision 与 attempt，记录每次模型调用延迟、实际调用次数、修复次数、校验错误签名、来源读取允许/拒绝原因与最终 SUCCESS / REPAIRED / FALLBACK。模型请求记录 extraction.v1 / repair.v1 话术版本，读取单独计时，不伪造 tool_call_id。报告区分 SDK 调用延迟与包含处理工作的 wrapper 耗时；普通事件不得嵌入敏感原值。来源是否已保存与提取是否成功分开表达，页面话术见上下文契约。

人工接管包含可靠保存失败负载及各次尝试证据、返回 reviewId、列表和详情查询，初始审核状态为 PENDING。已过保留期的原文引用明确标记到期。本次不实现人工编辑、关闭或重新处理；人工后续操作也不能抹去原执行的失败事实。

FastAPI 与 Gradio 同进程共用应用服务；UI 回调直接调用服务层。页面采用聊天形态并替换原表单页：自由文本默认补充当前任务；样例/记录下拉每次发送都新建任务；显式“新建任务”按钮控制下一条自由文本；当前任务状态条展示任务、来源条数、会话与待新建标记；页面提供会话复制/恢复/清空/新建、六字段结果与执行指标、流式阶段文本、FALLBACK 行动条及人工审核 tab。聊天阶段文本只是进度的只读投影，不改变模型无工具、预算、校验、修复与兜底边界。HTTP 映射表保持不变。页面实际提取使用配置供应商，缺少配置时明确报错，不静默切换模型替身。

页面展示每次运行的安全处理与修复事实（输入方式、来源版本、PII 类别与脱敏计数、标签中和数、失败阶段与安全错误签名、预算与模型错误码），这些事实随运行持久化并用于历史回放；页面不输出“是否注入/是否攻击”的判定。

| 情况 | HTTP 映射，仅适配器使用 |
|---|---:|
| SUCCESS / REPAIRED / 审核保存成功的 FALLBACK | 200 |
| 来源读取授权拒绝 | 403，不读取来源、不调用模型 |
| 请求字段不合法 | 422 |
| 输入或累计来源材料超限 | 413 |
| 同任务忙 | 409 |
| 会话过期 | 410 |
| 来源保存、审计/审核保存或内部处理失败 | 500 |

## 8. 验收与证据

自动化测试使用可编排模型替身，运行真实 middleware、图、来源读取策略与临时 SQLite；不得替换要验证的恢复控制流。模型替身测试无需付费 API，真实模型业务与注入评测独立运行和报告。

| 验收组 | 必须验证 |
|---|---|
| 正常提取 | 首次合法输出为 SUCCESS，六字段符合 schema；TX-001 客户 ID 与账单问题正确，已发起退款不误写为再次退款 |
| 修复恢复 | 非法 JSON、枚举/类型、缺字段、额外字段、超长摘要、空响应或意外工具调用触发同一修复预算；反馈关联正确原始证据、具体错误和安全副本；恢复为 REPAIRED |
| 预算与调用失败 | 两种输入模式模型均最多三次、额外修复最多两次；记录最多读取一次，修复不重复读取；持续失败进入可查询 PENDING；模型/来源读取异常不进入格式修复 |
| 人工与存储失败 | 审核保存失败不返回虚假 FALLBACK/reviewId；原文到期明确显示，不能借新审核延长原文保留 |
| 权限与注入 | 直接及记录内容注入；授权拒绝或策略故障时读取 handler 未执行；提取 Agent 工具配置为空，模型生成的工具调用不执行，来源无法扩大读取范围 |
| PII | TX-002 标记为 true；仅卡号尾号不单独触发；修正不清除历史标记；日志、错误、默认展示和修复材料不含已识别敏感原值；安全处理异常时不将原文外发模型 |
| 多轮与隔离 | 补充与最新明确修正生效；session/task 隔离；新运行重置预算，历史结果不冒充本次成功 |
| 上下文投影 | 首次为 system + 来源包，修复仅增加最近失败反馈；安全序列化与角色标签中和；模型实际输入无敏感原值、旧答案、旧修复或其他任务材料；反馈关联原始尝试，恶意额外字段名不进入可信错误文本 |
| 先保存来源 | 修正为 CUST-456 后模型失败，下一轮仍依据该修正；来源保存失败不调用模型；超限或并发拒绝不追加 |
| 生命周期 | 重新打开 SQLite 可恢复；第八天活跃会话靠脱敏来源继续，旧原文无法取回；脱敏损失不被猜测补齐；七天未使用过期与显式清空生效 |
| 中断 | 重启不调用模型、不重置旧运行计数；中断转人工；已接收来源保留，新提交获得新预算 |
| 模块边界 | 核心无需启动 Web 即可运行，不依赖 FastAPI/Gradio 或 HTTP 类型 |

真实模型评测至少覆盖四个原题样例、记录读取注入和多轮补充，记录供应商、模型、配置、话术版本、输入与实际结果，分别报告结构、业务语义和安全表现。加入同一业务材料添加攻击文字前后的分类和紧急程度一致性评测。语义口径如下：

- 误扣、发票、退款归 BILLING；崩溃或按钮故障归 TECHNICAL；账户锁定、凭证或权限归 ACCOUNT；证据不足归 OTHER。
- 严重安全事件或大范围关键服务中断支持 CRITICAL；临近期限且阻断关键业务支持 HIGH；普通功能故障通常 MEDIUM；一般咨询 LOW。
- TX-002 期望 TECHNICAL / HIGH；TX-003 期望 TECHNICAL / MEDIUM，不受攻击文字要求影响；TX-004 期望 OTHER。TX-004 本身不长，另构造超长输入和截断输出用例。

没有供应商配置时真实评测明确标记未执行；失败如实报告，不隐式重跑掩盖结果。替身测试证明控制流和边界，真实评测证明已测试样例表现，均不能证明所有内容真实或抵御所有注入。
