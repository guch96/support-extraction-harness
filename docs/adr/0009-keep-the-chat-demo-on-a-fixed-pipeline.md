# 聊天式演示保持固定提取链路，模型仍无工具

2026-10-19，用户要求一个类 codex/千问的聊天演示。参考项目 deer-flow 是带工具自主权的真 agent；本页面的聊天形态只改变输入与进度呈现，不改变提取角色和控制权。

## 背景

聊天界面容易让人期待“对话式 agent”：由模型决定读哪份记录、调用哪些工具、何时重试。deer-flow 正是这种真 agent。本项目的已确认边界相反：读取目标由代码确定，模型只负责从已提供的来源生成六字段 JSON；授权、预算、修复与兜底都由程序控制。

## 决策

聊天只是输入形态，不是新的执行角色。

- 提取角色仍无业务工具（`tools=[]`）；页面不注册、不转发也不执行模型提出的工具调用。
- 模型调用预算（最多 3 次）、唯一修复循环（最多 2 次额外修复）、FALLBACK 人工审核兜底、来源读取范围与注入缓解边界全部不变。
- 聊天阶段事件（`reading`、`calling_model`、`repairing`、`validating`、`succeeded`、`failed`）只是进度的只读投影：页面用它们替换占位气泡，不改变状态、预算、校验结论或跳转。
- 自由文本默认补充当前任务；样例/记录下拉和显式“新建任务”只决定提交到哪个 session/task，仍走同一个 `ExtractionService.submit` 与同一条提取链路。

## 备选

- **真 agent + 工具**：拒绝。控制权交给模型，读取面与提示词注入面扩大，且模型自主决策使评测不可复现；与 [ADR-0008](0008-use-one-tool-free-extraction-agent.md) 的代码授权取数冲突。
- **静态回放**：本期不做。预先录制的阶段与结果不能证明真实控制流，也不能随配置和失败路径变化。
- **保留表单页**：拒绝。用户已确认聊天式演示；聊天不是引入工具的理由。

## 后果

- 不能演示“模型自主选择工具”的能力；演示重点仍是固定链路下的校验、修复、兜底与可观测性。
- 页面体验依赖固定链路：阶段顺序、可展示字段和 FALLBACK 行动都由代码决定。
- 未来若要让模型获得业务工具或审批能力，需要新的 ADR 与独立的安全论证，不能只改页面。
